# Sonic Sprite Animation Viewer 개발 명세서

## 1. 목적과 기준 문서

`Labs/LEC09/PRE_PRD.md`를 기준으로 `sonic-sprite.png`의 모든 소닉 동작을 순서대로 재생하는 Python/pico2d 애니메이션 뷰어를 개발한다.

필수 요구사항은 다음과 같다.

1. 불규칙한 프레임 크기와 동작별 프레임 수를 반영한다.
2. 각 동작을 한 번 재생한 뒤 1초 동안 대기한다.
3. 마지막 동작의 대기를 마치면 첫 동작부터 반복한다.
4. `DRILL_09` 브랜치에서 단계별로 개발하고, 의미 있는 커밋을 최소 20개 남긴다.

이 문서는 개발 및 검증 기준이다. 커밋 계획과 테스트 항목은 앞으로 수행할 작업이며, 완료 사실을 의미하지 않는다.

## 2. 개발 환경과 산출물

| 항목 | 명세 |
| --- | --- |
| 언어 | Python 3 |
| 그래픽 라이브러리 | pico2d |
| 개발 브랜치 | `main`에서 생성한 `DRILL_09` |
| 작업 디렉터리 | `Labs/LEC09/` |

| 사전 요구사항 | `Labs/LEC09/PRE_PRD.md` |
| 상세 명세서 | `Labs/LEC09/PRD.md` |

실행 시 필요한 외부 라이브러리는 pico2d로 제한한다. 경로 처리와 시간 측정에는 Python 표준 라이브러리를 사용한다. 이미지 분석 도구를 개발 중 사용하더라도 실행 프로그램의 필수 의존성으로 추가하지 않는다.

저장소 루트에서 다음과 같이 실행한다.

```powershell
python Labs/LEC09/sonic-animation-viewer.py
```

이미지 경로는 현재 작업 디렉터리가 아닌 실행 파일의 위치를 기준으로 계산한다. `Labs/LEC09/`에서 직접 실행해도 같은 이미지를 읽어야 한다.

## 3. 범위와 기본 결정

### 3.1 포함 범위

- 원본 시트에 있는 소닉 본체의 모든 동작과 단일 포즈.
- 프레임마다 다른 위치, 너비, 높이와 동작마다 다른 프레임 수.
- 동작별 순차 재생, 마지막 프레임 유지, 1초 대기, 전체 반복.
- 창 닫기 및 `Esc` 입력에 의한 정상 종료.
- 프레임 목록 검증 및 실제 화면 검수.

### 3.2 제외 범위

- 상단 제목, 하단 제작자 문구, 장식 및 소닉 이외 캐릭터.
- 게임 이동, 충돌, 점프 물리, 배경 스크롤, 사운드.
- 재생 목록 편집 UI, 마우스 조작, 속도 조절 UI, 프레임 자동 탐지 기능.
- 원본 이미지 수정, 프레임별 이미지 파일 분리, 새 이미지 제작.

### 3.3 원문에 없는 항목의 기본값

다음은 구현을 위한 기본 결정이며, 원문에서 지정한 값은 아니다.

| 항목 | 기본값 또는 정책 |
| --- | --- |
| 창 크기 | 800 × 600 |
| 프레임 재생 속도 | 초당 10프레임, 프레임당 0.1초 |
| 확대 배율 | 모든 프레임에 동일한 4배 적용 |

| 대기 중 화면 | 현재 동작의 마지막 프레임 유지 |

확대 후 가장 큰 동작이 창을 벗어나면 전체 배율을 동일하게 낮춘다. 프레임마다 화면에 맞춰 다른 배율을 적용하지 않는다. 재생 속도와 배율은 코드 상단 상수로 관리한다.

## 4. 스프라이트 시트 분석과 데이터 확정

### 4.1 분석 원칙

원본은 균일한 격자 시트가 아니다. `frame_index * width` 형태의 고정 간격 계산으로 모든 프레임을 자르지 않는다. 각 프레임의 사각형을 명시적으로 기록한다.

시각적으로 한 행에 있다는 이유만으로 같은 동작이라고 단정하지 않는다. 포즈 변화와 연속성을 확인해 동작 경계를 정한다. 한 동작이 여러 행에 이어지면 하나의 동작 목록에 연결한다. 이름이 불확실한 동작은 `action_01`처럼 중립적인 식별자를 사용한다.

### 4.2 개발 초기에 확정할 목록

실제 재생 코드보다 먼저 모든 소닉 프레임을 조사한다. 동작 수와 프레임 수는 현재 명세에서 추정해 고정하지 않는다. 조사 후 아래 목록을 이 문서에 추가하고 실행 코드의 데이터와 일치시킨다.

| 기록 항목 | 내용 |
| --- | --- |
| 동작 순번 및 ID | 중복 없는 식별자와 재생 순서 |
| 시트 위치 | 해당 동작이 차지하는 행 또는 영역 |
| 프레임 목록 | 재생 순서대로 정렬한 프레임 사각형 |
| 프레임 수 | 목록 길이에서 계산한 값 |
| 기준점 | 프레임별 정렬 기준 좌표 |
| 비고 | 행 연결, 단일 포즈, 분리된 효과 등 주의사항 |

조사 결과에는 전체 동작 수와 전체 프레임 수도 기록한다. 제외한 시트 영역은 제목, 제작자 표시, 다른 캐릭터 등 제외 이유를 남긴다. 모든 소닉 영역이 목록에 대응하는지 원본과 대조한다.

### 4.3 프레임 데이터 형식

실행 파일 안에 동작 목록을 선언한다. 별도 설정 파일이나 데이터베이스는 만들지 않는다.

각 동작은 `id`와 순서 있는 `frames`를 가진다. 각 프레임은 다음 값을 가진다.

| 필드 | 의미 |
| --- | --- |
| `left` | 원본 이미지 왼쪽에서 사각형 왼쪽까지의 픽셀 거리 |
| `top` | 원본 이미지 위쪽에서 사각형 위쪽까지의 픽셀 거리 |
| `width`, `height` | 원본 픽셀 기준 사각형 크기 |
| `anchor_x`, `anchor_y` | 잘린 사각형의 좌상단 기준 정렬점 |

기본 정렬점은 발밑 중앙으로 잡는다. 구르기나 공중 포즈처럼 발 기준이 부적절한 경우 몸체의 일관된 기준점을 지정한다. 모든 프레임의 정렬점을 화면의 공통 기준점에 맞춰 불필요한 흔들림을 줄인다. 원래 동작에 포함된 자세 변화는 유지한다.

프레임 사각형은 소닉과 해당 프레임의 효과를 모두 포함하되, 이웃 프레임이나 글자는 포함하지 않는다. 분리된 픽셀 효과를 별도 동작으로 잘못 세지 않는다.

### 4.4 좌표 변환과 유효성

pico2d의 이미지 자르기는 좌하단 기준 좌표를 사용한다. 원본 이미지 높이를 `sheet_height`라고 할 때 다음과 같이 변환한다.

```text
bottom = sheet_height - top - height
```

시작 시 모든 프레임에 대해 다음 조건을 검사한다.

- 동작 목록과 각 동작의 프레임 목록이 비어 있지 않다.
- 동작 ID가 중복되지 않는다.
- `width > 0`, `height > 0`이다.
- `left >= 0`, `top >= 0`이다.
- `left + width <= sheet_width`이다.
- `top + height <= sheet_height`이다.
- 정렬점은 해당 프레임 사각형 안에 있다.

잘못된 데이터는 동작 ID와 프레임 번호를 포함한 오류로 알린다.

## 5. 렌더링 명세

1. 캔버스를 열고 원본 이미지를 한 번만 읽는다.
2. 매 반복마다 배경을 지운다.
3. 현재 프레임의 사각형을 변환해 `clip_draw`로 그린다.
4. 캔버스를 갱신한다.

화면 기준점을 `(origin_x, origin_y)`, 배율을 `scale`이라고 하면 `clip_draw`의 중심 좌표와 표시 크기는 다음과 같다.

```text
draw_x = origin_x + (width / 2 - anchor_x) * scale
draw_y = origin_y + (anchor_y - height / 2) * scale
draw_width = width * scale
draw_height = height * scale
```

원본의 투명도 유무는 구현 시 확인한다. 투명한 영역은 그대로 사용하며, 불투명한 바탕색이 있으면 캔버스 배경을 원본 바탕색과 맞춘다. 확대 시 픽셀이 번지거나 외곽이 잘리지 않는지 실제 화면에서 확인한다.

## 6. 재생 상태와 시간 처리

### 6.1 상태

최소 상태는 현재 동작 번호, 현재 프레임 번호, `PLAYING` 또는 `WAITING`, 현재 상태의 경과 시간, 실행 여부다. 별도 상태 관리 프레임워크를 도입하지 않는다.

| 현재 상태 | 조건 | 처리 |
| --- | --- | --- |
| 시작 | 초기화 완료 | 첫 동작의 첫 프레임부터 `PLAYING` |
| `PLAYING` | 현재 프레임 표시 시간이 지남 | 다음 프레임으로 이동 |
| `PLAYING` | 마지막 프레임 표시 시간까지 지남 | 마지막 프레임을 유지하고 `WAITING` |
| `WAITING` | 대기 시간 1초 미만 | 마지막 프레임 유지, 이벤트 처리 계속 |
| `WAITING` | 대기 시간 1초 이상 | 다음 동작 첫 프레임으로 이동, `PLAYING` |
| 마지막 동작의 `WAITING` | 대기 완료 | 첫 동작 첫 프레임으로 복귀 |
| 모든 상태 | 창 닫기 또는 `Esc` | 반복 종료 및 캔버스 정리 |

동작별 프레임 수는 해당 목록의 길이로 판단한다. 마지막 프레임에도 다른 프레임과 동일한 기본 표시 시간을 준 다음, 추가로 1초 대기한다. 마지막 동작에도 동일한 대기를 적용한다.

### 6.2 시간 기준

`time.perf_counter()`와 같은 단조 증가 시계로 경과 시간을 계산한다. 렌더링 횟수에 의존해 애니메이션 속도를 결정하지 않는다.

긴 `delay(1.0)` 또는 `sleep(1.0)`으로 동작 간 대기를 구현하지 않는다. 대기 중에도 매 반복에서 이벤트를 처리하고 화면을 갱신한다. CPU 사용량을 줄이기 위한 짧은 반복 지연은 허용하되 재생 시간의 기준으로 사용하지 않는다.

정상적인 시간 오차는 누적 잔여 시간으로 보정한다. 창 이동이나 디버깅으로 긴 정지가 발생하면 전체 재생 목록을 한꺼번에 건너뛰지 않도록 한 번에 반영하는 경과 시간을 최대 한 프레임 시간으로 제한한다. 이 경우 재생 시간은 늘어날 수 있지만 모든 프레임의 표시 순서는 보존한다. `WAITING`에 진입할 때는 별도의 대기 시간을 시작해 실제 1초 대기를 확보한다.

### 6.3 예시 타임라인

10 FPS에서 3프레임짜리 동작은 각 프레임을 0.1초씩 표시한다. 마지막 프레임의 기본 표시가 끝나는 약 0.3초 시점부터 추가 1초 동안 유지한다. 다음 동작은 약 1.3초 시점에 시작한다. 단일 포즈도 0.1초 표시 후 1초 대기한다.

## 7. 코드 구조와 오류 처리

실행 파일 하나에 상수, 프레임 데이터, 데이터 검증, 상태 갱신, 그리기, `main()`을 배치한다. 상태 전이 계산은 시간 값을 인자로 받을 수 있게 구성해 실제 대기 없이 검증할 수 있도록 한다. 필요 없는 클래스 계층이나 범용 애니메이션 엔진은 만들지 않는다.

- `if __name__ == '__main__':`에서 프로그램을 시작한다.
- 이벤트는 재생 상태와 대기 상태 모두에서 처리한다.
- 정상 종료와 실행 중 예외 모두에서 열린 캔버스를 정리한다.
- 이미지가 없거나 읽히지 않으면 실패한 경로를 포함해 오류를 알린다.
- pico2d가 없으면 설치가 필요한 라이브러리 이름을 알린다.
- 로딩 실패 후 빈 화면을 계속 표시하지 않는다.

## 8. 단계별 개발 및 커밋 계획

아래 22단계를 기본 계획으로 사용한다. 각 커밋은 실제 변경과 확인 결과가 있는 독립적인 단계여야 한다. 빈 커밋이나 의미 없는 변경으로 개수를 채우지 않는다. 데이터 등록 단계는 시트 조사에서 확인한 동작 묶음에 맞춰 조정할 수 있다.

| 순서 | 개발 내용 | 해당 단계 확인 사항 |
| --- | --- | --- |
| 1 | 상세 개발 명세서 추가 | 원문 필수 요구사항 반영 |
| 2 | 전체 동작 및 제외 영역 목록 확정 | 원본 모든 소닉 영역 대응 |

| 5 | 프레임 데이터 형식과 첫 동작 등록 | 실제 좌표와 목록 순서 |
| 6 | 좌표 변환 및 단일 프레임 그리기 | 상하 좌표 및 잘림 확인 |
| 7 | 공통 배율과 기준점 정렬 | 크기 비율 및 위치 확인 |

| 15 | 동작 종료 후 1초 대기 | 마지막 프레임 유지 |
| 16 | 마지막 동작에서 첫 동작으로 반복 | 마지막 대기 후 처음으로 복귀 |
| 17 | 재생 및 대기 중 종료 이벤트 처리 | 창 닫기와 `Esc` 응답 |
| 18 | 긴 정지 이후 시간 처리 보완 | 대량 프레임 건너뜀 방지 |
| 19 | 로딩 오류 안내 및 예외 시 자원 정리 | 누락 이미지 오류와 창 정리 |
| 20 | 최소 자동 검증 추가 | 프레임 수 차이와 상태 경계 검증 |
| 21 | 전체 시각 검수 및 확인된 좌표 보정 | 이웃 프레임 혼입 및 흔들림 확인 |
| 22 | 실행 방법과 최종 검증 결과 기록 | 완료 기준 및 커밋 수 확인 |

21단계에서 좌표 보정이 필요 없으면 검수 결과를 기록한다. 단계를 합치거나 바꾸더라도 완료 시 신규 개발 커밋은 최소 20개여야 한다. 이 명세서 작성 요청만으로 위 구현과 커밋을 실행하지 않는다.

커밋 메시지는 변경 내용을 구체적으로 작성한다. 개발 시작 기준점은 `DRILL_09` 생성 시점의 커밋 해시로 기록한다. 기존 조상 커밋은 개수에 포함하지 않는다. `git rev-list --count <개발_시작_커밋>..DRILL_09`와 커밋 로그로 개수와 내용을 함께 확인한다. 커밋 수를 줄이는 squash는 완료 검증 전에 수행하지 않는다.

## 9. 검증 계획

### 9.1 최소 자동 검증

새 테스트 프레임워크 없이 표준 라이브러리 또는 간단한 `assert` 기반 검증을 사용한다. 필요하면 `Labs/LEC09/test_sonic_animation_viewer.py` 하나를 추가한다. 그래픽 창 없이 데이터 및 시간 전이를 확인할 수 있어야 한다.

| 항목 | 검증 기준 |
| --- | --- |
| 원본 범위 | 모든 사각형이 실제 이미지 크기 안에 있음 |
| 좌표 변환 | 위쪽 끝과 아래쪽 끝의 사각형을 올바르게 변환 |
| 다른 프레임 수 | 1프레임 동작과 여러 프레임 동작 모두 범위 초과 없음 |
| 마지막 프레임 | 기본 표시 시간을 모두 채운 뒤 대기 진입 |
| 대기 경계 | 1초 직전에는 유지, 1초 도달 시 다음 동작 전환 |
| 전체 반복 | 마지막 동작의 대기 후 첫 동작 첫 프레임 |
| 긴 정지 | 한 번의 갱신으로 여러 동작을 건너뛰지 않음 |

### 9.2 수동 실행 검증

- 저장소 루트와 `Labs/LEC09/`에서 각각 실행한다.
- 원본 목록과 재생 화면을 대조해 모든 동작을 확인한다.
- 작은 프레임, 큰 프레임, 구르기, 공중 포즈에서 잘림과 기준점 흔들림을 확인한다.
- 제목, 제작자 문구, 다른 캐릭터 또는 이웃 프레임이 나타나지 않는지 확인한다.
- 일반 실행 환경에서 각 동작 종료 후 대기 시간이 1초인지 확인한다. 측정 허용 오차는 한 번의 화면 갱신 간격으로 한다.
- 전체 목록을 최소 2회 반복해 순서 유지와 반복 경계를 확인한다.
- 재생 중과 대기 중에 각각 `Esc` 및 창 닫기를 시험한다.
- 존재하지 않는 이미지 경로를 사용하는 검증 상황에서 오류 안내와 캔버스 정리를 확인한다. 원본 자산은 삭제하지 않는다.
