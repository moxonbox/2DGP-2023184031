## 동작 구분·데이터

- 행 중심으로 분류한다. 1행은 전체를 한 동작으로 통합한다. 8행의 공중 회전/쓰러짐, 10행의 피격/대기는 서로 다른 포즈이므로 분리한다. 행 내부는 왼쪽부터 재생한다.
- 원본 399×525 RGBA, 배경 알파 0. 제목(y=0~32), 제작자 문구·하단 색상 변형 예시(y≥469)는 제외한다. 본문과 해당 프레임 효과는 모두 포함한다.
- 실행 파일에 `id`, 순서 있는 `frames`, 선택 필드 `fps`, `move`, `speed`를 선언한다. `fps` 기본값 12, `move` 기본값 False, `speed` 기본값 200px/활성 초. 공식 동작명은 없으므로 ID는 중립적으로 유지한다.
- 아래 이동 지정은 걷기·달리기·구르기에 적용한다. 공중 회전·피격·균형·대기는 제자리 동작이다.

- 프레임: `(left, top, width, height, anchor_x, anchor_y)`. 원본 좌상단 기준 사각형과 사각형 내부 좌상단 기준 정렬점. 좌표는 코드에만 유지한다.
- 고정 격자 계산·런타임 프레임 탐지·별도 설정 파일·DB·프레임 이미지 분리·원본 수정은 금지한다.
- 정렬점은 발밑 중앙 또는 공중/회전 포즈의 일관된 몸체 기준점. 자세 변화는 유지하고 불필요한 흔들림은 줄인다.
- 시작 시 검사: 비어 있지 않은 목록, 고유 ID, 정수 사각형·양수 크기·이미지 경계, 유한한 내부 정렬점, 유한한 양수 FPS(≤60), bool `move`, 유한한 양수 `speed`. 프레임은 길이 6의 tuple/list만 허용하며 None·정수·문자열 등은 ID·프레임 번호를 포함한 ValueError로 안내한다. 오류에 동작 ID와 해당 프레임 번호를 표시한다.

## 재생·이동·대기

1. 첫 동작 첫 프레임부터 뷰포트 중앙에서 **정확히 3회** 전체 프레임을 재생한다. 회차 사이 대기는 없다.
2. 제자리 동작은 세 번째 회차 마지막 프레임의 기본 표시 시간 후 1초 대기한다.
3. 이동 동작은 3회 재생 후 첫 프레임으로 돌아가 왼쪽 끝에서 시작한다. **왼쪽→오른쪽 편도 이동 1회**, 동작별 `speed` 적용(표 참조), 생략 시 200px/활성 초. 왕복·화면 밖 출발·퇴장은 하지 않는다.
4. 이동 중에는 같은 동작의 애니메이션을 계속 반복한다. 이는 제자리 3회 재생과 별개다. 오른쪽 끝 도달 시 이동·애니메이션을 멈추고 도달 프레임을 1초 유지한다.
5. 대기 후 다음 동작의 중앙·첫 프레임·회차 0으로 초기화한다. 마지막 동작도 동일하게 대기한 뒤 첫 동작으로 돌아가 무한 반복한다.

- 상태: 동작/프레임 번호, 완료 회차, 재생 경과 시간, 이동 여부·수평 오프셋, 대기 여부, 최소화 정지 여부. 동작 길이는 `len(frames)`로 판단한다.
- 프레임 표시 시간은 `1 / action_fps`. 매 회차 마지막 프레임도 기본 시간을 채운다. 제자리 재생·이동·대기는 각각 별도 시간 경계로 처리하며 이전 단계의 잔여 시간을 넘겨 조기 종료하지 않는다.
- `time.perf_counter()` 사용. 정상 재생의 잔여 시간은 보정하며 화면 갱신당 최대 한 프레임만 전진한다. 느린 렌더링에서는 프레임 표시를 우선하고 재생 시간 연장을 허용한다.
- `dt > 0.5초`는 긴 정지로 처리해 재생·이동·대기에 더하지 않는다. 최소화 중에는 이벤트만 처리하고 모든 시간을 정지한다. 복원 시 시계 기준을 재설정하되 회차·프레임·위치·잔여 시간을 유지한다.
- FPS 오차 정책: 마지막 프레임의 최소 표시 시간 보장을 우선한다. 정상 잔여 시간 보정 중 마지막 프레임 진입 시 잔여 시간을 초기화하므로 주기가 소폭 길어질 수 있다. 렌더링 30/60/144 FPS에서 제자리 3회 단계의 이론값 대비 오차를 0~`2*ACTION_LOOPS/render_fps`초로 검증한다(이동·대기·정지 제외).
- 렌더링 목표는 60 FPS. 1초 대기를 긴 `delay/sleep`으로 막지 않는다. 이벤트를 계속 처리하며 CPU 절약용 짧은 반복 지연만 사용한다.
- 이론 시간: 제자리 `3*N/FPS + 1`; 이동 `3*N/FPS + (800 - 표시된 동작 경계 너비)/speed + 1`초. 반올림·화면 갱신·정지로 실제 시간은 늘어날 수 있다.

## 뷰포트·렌더링

- 800×600 고정 창. 동적 크기 조절, 게임 물리·충돌·사운드·편집 UI는 구현하지 않는다. 수평 이동은 위 재생 시연에만 사용한다.
- 동작의 정렬 경계 상자 긴 변을 작은 변의 1/3인 **200px**에 맞춘다. 효과 포함, 종횡비 유지, 같은 동작에서는 동일 배율. 동작 간 배율 차이는 허용한다.

```text
프레임 정렬 범위: x=[-anchor_x, width-anchor_x], y=[anchor_y-height, anchor_y]
xmin/xmax/ymin/ymax = 전체 프레임 범위의 최솟값/최댓값
W = xmax-xmin; H = ymax-ymin; cx = (xmin+xmax)/2; cy = (ymin+ymax)/2
s = 600 / (3 * max(W,H))
ox = 400 - cx*s; oy = 300 - cy*s
limit = (800 - W*s)/2
제자리 offset=0; 이동 offset=-limit에서 +limit까지 증가
x = ox + (width/2-anchor_x)*s + offset
y = oy + (anchor_y-height/2)*s
clip bottom = sheet_height-top-height; 표시 크기 = (width*s, height*s)
```

- 좌우 끝은 동작 전체 경계 상자가 각각 x=0·x=800에 접하는 위치다. 모든 프레임이 뷰포트 안에 있어야 한다. 반전 없이 오른쪽으로 이동하고 y·배율은 유지한다.
- 단일 실행 파일에 상수·데이터·검증·상태·그리기·`main()`을 둔다. 범용 엔진·불필요한 클래스 계층은 만들지 않는다. 시간 값을 주입해 창 없이 검증 가능하게 한다.
- 이미지 1회 로딩, 배율·이동 경계 사전 계산. 매 반복: 이벤트 → 상태 → 지우기 → `clip_draw` → 갱신. 투명 영역 유지, 기본 격자는 숨긴다.
- `pico2d.pico2d` 모듈에서 캔버스 핸들을 읽는다. `get_events()`가 창 이벤트를 반환하지 않으므로 `SDL_GetWindowFlags(window)`로 최소화를 감지한다.
- 창 제목에 동작 ID·회차(1/3~3/3)·단계(재생/이동/대기), 최소화 시 일시정지를 표시한다. pico2d가 이벤트 처리 중 제목을 덮어쓰므로 상태 갱신 후 제목을 설정한다. 별도 폰트·HUD 라이브러리는 추가하지 않는다.
- 모든 상태에서 Esc·창 닫기 종료, 정상/예외 모두 캔버스 정리. 이미지 실패는 경로, pico2d 누락은 라이브러리 이름을 알리고 종료한다.
