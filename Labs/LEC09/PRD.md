# Sonic Animation Viewer — AI 개발 지시

## 목표·산출물

- 기준: `PRE_PRD.md`. 작업 경로: `Labs/LEC09/`. 경로의 `_`는 실제 문자다.
- Python 3 + pico2d로 `sonic-animation-viewer.py`를 구현한다. 런타임 의존성은 pico2d와 표준 라이브러리만 사용한다.
- 원본 `sonic-sprite.png`의 모든 소닉 동작·단일 포즈를 순차 재생한다. 프레임별 크기와 동작별 프레임 수 차이를 반영한다.
- 각 동작 1회 재생 → 마지막 프레임에서 추가 1초 대기 → 다음 동작. 마지막 동작도 대기 후 처음부터 반복한다.
- `main`에서 생성한 기존 `DRILL_09`에서 개발한다. 신규 유의미한 커밋 최소 20개. 명세 편집 요청만으로 구현·커밋을 시작하지 않는다.

## 범위·기본값

- 제외: 제목·제작자 문구·장식·타 캐릭터, 게임 기능·사운드·편집/속도 조절 UI·런타임 프레임 자동 탐지.
- 원본 수정, 프레임 이미지 분리, 새 이미지 생성 금지.
- 뷰포트는 800×600 고정. 실행 중 창 크기 조절·동적 뷰포트 처리는 구현하지 않는다.
- 애니메이션 FPS는 자연스러운 동작 속도로 정한다. 기본 12 FPS로 시작해 시각 검수로 조정하고, 필요한 동작에만 개별 FPS를 지정한다. 렌더링 FPS와 분리한다.
- 스프라이트 목표 크기는 작은 변의 1/3인 200px. 효과를 포함한 동작 전체 정렬 경계 상자의 긴 변을 맞추고 종횡비를 유지한다. 같은 동작 안에서는 배율을 고정한다. 동작 간 배율 차이와 효과 때문에 본체가 작아지는 것은 허용한다.
- 동작 순서는 위→아래, 같은 영역은 왼쪽→오른쪽. 포즈 연속성으로 경계를 판단하며 행과 동작을 동일시하지 않는다.

## 프레임 조사·데이터

- 재생 구현 전에 시트를 조사한다. 동작/프레임 수를 추정해 고정하지 않는다. 여러 행에 걸친 동작은 연결한다.
- 동작별 ID·시트 영역·프레임 수·주의사항, 전체 동작/프레임 수, 제외 영역/이유만 이 문서에 짧게 기록한다. 원본 모든 소닉 영역과 대조하며 좌표·코드는 문서에 중복하지 않는다.
- 실행 파일에 `id`, 순서 있는 `frames`, 선택 필드 `fps`를 선언한다. `action_fps = action.get('fps', DEFAULT_FPS)`, 기본값 12. 불명확한 이름은 `action_01` 등으로 지정한다. 별도 설정 파일·DB 불필요.
- 프레임: `(left, top, width, height, anchor_x, anchor_y)`. 원본 좌상단 기준 사각형과 사각형 내부 좌상단 기준 정렬점. 좌표의 원본은 코드에만 유지한다.
- 고정 격자 계산 금지. 소닉과 해당 효과를 포함하고 이웃 프레임·글자는 제외한다. 분리된 효과를 별도 동작으로 세지 않는다.
- 정렬점은 발밑 중앙, 구르기·공중 포즈는 일관된 몸체 기준점. 불필요한 흔들림을 줄이되 원래 자세 변화는 유지한다.
- 시작 시 검사: 비어 있지 않은 동작/프레임 목록, 고유 ID, 정수 사각형 좌표·양수 크기, 이미지 내부 사각형, 유한한 프레임 내부 정렬점, 유한한 양수 FPS. 오류에 동작 ID와 해당 시 프레임 번호를 포함한다.

## 렌더링·구조

- 개발 시작 시 실제 Python 실행 경로·pico2d 버전과 캔버스/이벤트 API를 확인하고 기록한다. 설치된 IDE 인터프리터를 우선 사용한다.
- 이미지 경로는 `__file__` 기준. 고정 캔버스를 열고 이미지는 1회 로드한다. 매 반복: 이벤트 처리 → 상태 갱신 → 배경 지우기 → `clip_draw` → 화면 갱신.
- 동작의 모든 프레임을 정렬점 기준으로 겹친 경계 상자 크기를 `(action_width, action_height)`, 중심을 `(cx, cy)`로 계산한다. 화면 기준점은 이 상자가 뷰포트 중앙에 오도록 잡는다.
- 이미지 높이 `H`, 뷰포트 크기 `(vw, vh)`일 때:

```text
프레임별 정렬 범위: x=[-anchor_x, width-anchor_x], y=[anchor_y-height, anchor_y]
xmin/xmax/ymin/ymax = 모든 프레임 범위의 최솟값/최댓값
action_width = xmax - xmin; action_height = ymax - ymin
cx = (xmin + xmax) / 2; cy = (ymin + ymax) / 2
bottom = H - top - height
s = min(vw, vh) / (3 * max(action_width, action_height))
ox = vw / 2 - cx * s
oy = vh / 2 - cy * s
x = ox + (width / 2 - anchor_x) * s
y = oy + (anchor_y - height / 2) * s
표시 크기 = (width * s, height * s)
```

- 경계 상자는 위쪽이 양수인 화면 좌표 기준. 배율·기준점은 동작별로 미리 계산한다. 최소화 중에는 이벤트 처리만 계속하고 그리기·재생·대기 시간을 정지한다. 복원 시 마지막 시각을 재설정하고 기존 동작·프레임·잔여 시간을 유지한다.
- 투명도는 실제 파일에서 확인한다. 투명 영역은 유지하고 불투명 바탕이면 배경색을 맞춘다. 확대·축소 번짐·잘림을 검수한다.
- 단일 실행 파일: 상수·데이터·검증·상태 갱신·그리기·`main()`과 실행 가드. 불필요한 클래스 계층·범용 엔진 금지.
- 시간 갱신은 시간 값을 주입해 창 없이 검증할 수 있게 한다.
- 재생/대기 모두 `Esc`·창 닫기로 종료. 정상 종료·예외 모두 열린 캔버스를 정리한다.
- 이미지 로딩 오류는 경로, pico2d 누락은 라이브러리 이름을 알리고 종료한다.

## 시간·상태

- 상태: 동작 번호, 프레임 번호, `PLAYING/WAITING`, 경과 시간, 실행 여부. 동작 길이는 `len(frames)`로 판단한다.
- `PLAYING`: 첫 프레임부터 각 `1 / action_fps`초 표시. 마지막 프레임의 기본 표시 시간까지 채운 뒤 `WAITING`.
- `WAITING`: 마지막 프레임 유지. 진입 시 별도로 측정한 활성 경과 시간 1초가 지나면 다음 동작 첫 프레임으로 전환. 최소화·긴 정지 시간은 제외한다. 마지막 동작이면 첫 동작으로 복귀.
- 단일 포즈도 `1 / action_fps`초 표시 + 1초 대기. N프레임 동작의 정상 소요 시간은 `N / action_fps + 1`초다.
- 단조 증가 시계 `time.perf_counter()` 사용. 정상 지연은 누적 잔여 시간으로 보정한다. 프레임 생략은 금지하고 화면 갱신당 최대 한 프레임만 전진한다. 렌더링이 애니메이션 FPS보다 느리면 전체 표시를 우선하며 소요 시간 연장을 허용한다.
- 긴 정지 기준은 `dt > 0.5초`: 해당 시간은 재생·대기에 더하지 않고 시계 기준만 재설정한다. 일반 갱신마다 `dt`를 한 프레임 시간으로 잘라 버리지 않는다. 대기 진입 시 이전 재생 잔여 시간을 대기로 넘기지 않는다.
- 렌더링 목표는 60 FPS(기본값), `action_fps`는 렌더링 목표 이하로 지정한다. 재생 속도는 반복 횟수가 아닌 경과 시간으로 결정한다.
- 1초 대기를 `delay/sleep`으로 막지 않는다. 대기 중에도 이벤트·화면 갱신을 계속한다. CPU 절약용 짧은 지연만 허용한다.
